# رفيق — بوابات النسخة المرخّصة لتجربة صاحب متجر وعماله

**الهدف:** تجربة تشغيلية محدودة لصاحب متجر وعماله على **هواتف منفصلة**، لا توزيع نسخة التطوير العامة على أنها منتج نهائي. نجاح GitHub Actions #79 (323 اختبار Android) لا يثبت أن البيع والطباعة والصوت والمزامنة والرخصة تعمل على الأجهزة الحقيقية.

## ما يلزم قبل تسليم متجر بياناته الحقيقية

1. **ترخيص صالح لكل هاتف ضمن اشتراك متجر واحد:** تطبيق «رفيق للمالك» على هاتف مورّد البرنامج وحده يصدر الرخص. مفتاحه الخاص لا يغادر الهاتف. يرسل المتجر معرّف كل جهاز؛ تصدر رخصة مختلفة لهاتف المالك ولكل هاتف عامل، باسم المتجر والمدة نفسها. رمز جهاز واحد لا يعمل في جهاز آخر. المفتاح **العام فقط** يُضاف سراً لبناء Android Release على GitHub Actions. نسخة Debug الحالية بلا مفتاح عام ليست نسخة مرخّصة. لا تغيّر توقيع التطبيق من دون إذن صاحب المشروع وخطة انتقال بيانات.
2. **مزامنة حقيقية مؤمّنة بين الهاتفين:** وجود الرخصة وحدها لا ينقل بيعاً أو ديناً. حالياً لكل هاتف قاعدة محلية منفصلة، ولا يوجد خادم مزامنة أو إقرار قيد أو منع تكرار على مستوى الخادم. لا تُسلّم نسختان مستقلتان لمتجر يكتب العامل وصاحبه فيه ديوناً. يجب ضبط قاعدة/خادم مركزي بصلاحيات متجر ومستخدم (RLS/هوية متحقق منها)، معرّفات عالمية للزبائن، UUID لكل طلب قابل للإعادة، نتائج «معلّق/قُبل/رُفض»، وتسوية الصندوق/المخزون وعدم افتراض تطابق فوري عند انقطاع الإنترنت. اختبر دخول عامل وإلغاء صلاحية جهاز مفقود وتعامل الطلبات المكررة قبل بيانات حقيقية.
3. **سلامة البيانات:** النسخة المشفّرة والتأكد منها متاحان، لكن **الاستعادة من الشاشة لم تُختبر أو تُفعّل**. لا تجربة مالية فعلية قبل اختبار استعادة كاملة على هاتف تجريبي ونسخة نجاة للحالة الحالية، ومنع تكرار قيد البيع عند انقطاع الرد. لا يوجد تراجع جماعي عن استيراد الأصناف أو حركات المال.
4. **كتالوج حقيقي:** ملف الأصناف المرفق يحوي 34/38 رقماً من 13 خانة لا تتطابق مع رقم تحقق EAN‑13؛ قد تكون رموزاً داخلية بترميز آخر، ولا تثبت الأسماء/الأسعار. طابق باركود العبوة والعملة والسعر والكمية مع المتجر قبل الحفظ. نقل ديون كناش محظور حتى تتأكد العملة ومطابقة الزبائن، ولا تُعلن قراءة صور المشتريات المختلطة آلياً قبل تنفيذها.
5. **الاختبار والتسليم:** جرّب على هاتفين فعليين برخصتيهما؛ بيع نقدي وآجل، دين من كل هاتف، مسح EAN/CODE128، طباعة، مشاركة PDF، إلغاء فاتورة، نسخ/استعادة، انقطاع وعودة الإنترنت، وإغلاق وفتح التطبيق. طابق الأرصدة والتسلسل والتقارير بعد العودة. أرسل ملاحظات المتجر دون تصوير بيانات زبائن خاصة قدر الإمكان؛ دوّن كل عطل مرقماً قبل إصلاحه. إذا فشل شرط، لا تصف البناء بأنه «جاهز للبيع».

## مدخلات من صاحب المشروع لا يمكن توليدها في المستودع

- تجربة تطبيق «رفيق للمالك» على هاتفه لاستخراج **المفتاح العام فقط**؛ المفتاح الخاص يبقى على هاتفه. ثم وضع المفتاح العام في GitHub Secrets باسم `RAFIQ_LICENSE_PUBKEY` لبناء Release.
- عنوان مشروع المزامنة الفعلي (`Project URL`)، المنطقة، ومفتاح الاستخدام العام `publishable/anon` إن كان المشروع جاهزاً، وخطوة يوافق عليها لإنشاء جداول وصلاحيات المشروع. **لا** تُنسخ كلمات مرور أو مفاتيح `service_role`/`sb_secret_` إلى تطبيق الهاتف أو هذا المستودع.
- موافقة صريحة قبل تغيير توقيع تطبيق رفيق أو تطبيق المالك؛ التوقيع الحالي يبقى كما هو حتى ذلك القرار. تحديد صاحب متجر تجريبي وهواتفه عند اكتمال جميع البوابات.

**ما أُنجز في هذه المرحلة:** سُجّلت البلاغات #62–#64 قبل الإصلاح؛ شُدّد إصدار الرخصة لمنع الاسم/المدة غير الصالحين، ومُنع زر نسخ رسالة انتظار المفتاح العام، وأُضيفت اختبارات تطبيق المالك وخطوات CI لرفض بناء Release بمفتاح مزيف أو مفقود، حتى عبر أمر `assemble` العام. هذه التعديلات لا تثبت نجاح الاختبارات أو عمل الهاتف قبل تشغيل CI والتجربة. لم تُنشأ رخصة حقيقية، ولم تُنشر مزامنة، ولم تُختبر النسخة على هاتف بعد؛ لا تسلّم APK التطوير لمتجر ببيانات حقيقية.
