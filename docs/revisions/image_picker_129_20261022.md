# مراجعة 129 — فتح صور الهاتف وصورة الزبون

القاعدة: f989a30 (واجهة 128). versionCode الأدنى 129، versionName 0.3.3. نفس applicationId ومفتاح التوقيع. بناء Android على GitHub فقط.

## سبب المراجعة

بلاغ المالك بعد تجربة 128 على الهاتف: زر «اختيار ملف» غير فعال (لا يفتح منتقي الصور)، وحقل الصورة يظهر دائمًا مع كل «عرض الدين» ولا يريده ظاهرًا.

## عقود المراجعة

1. فتح أي `<input type="file" accept="image/*">` في الواجهة (صورة الزبون، شعار المتجر، صورة المورّد) يتم عبر `WebChromeClient.onShowFileChooser` و`ACTION_OPEN_DOCUMENT` — لا جسر JavaScript جديد، وقائمة الجسور الخمسة المراجعة لا تتغير.
2. المنتقي يفتح من صفحة `/assets/pilot/index.html` الموثوقة وحدها، ووضعه `MODE_OPEN` مفرد بلا تعدد.
3. الحدود: نوع MIME من `image/jpeg|image/png|image/webp`، والحجم المعلوم بين 1 بايت و10 ميغابايت (حجم غير معلوم من مزوّد سحابي يُقبل لأن المزوّد لم يكشفه، والحفظ يُصغّر الصورة إلى 160px)، والعنوان `content://` بسلطة صريحة. أي غير ذلك يُرفض بإتمام فارغ ورسالة صريحة.
4. إكمال واحد لكل طلب: اختيار/إلغاء/إتلاف النشاط يُفرغ `imageCallback` مرة واحدة ولا يترك حقل إدخال عالقًا. طلب ثانٍ والمنتقي مفتوح يُلغى صراحةً ولا يُستبدل.
5. لا أذونات تخزين جديدة؛ قراءة الـ URI المختار فقط عبر `FLAG_GRANT_READ_URI_PERMISSION`. `file://` و`content://` كتنقل/شبكة يبقى رفضها من سياسة الاعتراض الحالية.
6. قسم «صورة الزبون» في بطاقة الرصيد مطوي افتراضيًا خلف «📷 صورة الزبون (اختياري)»؛ لا حقل ملف ظاهر مع كل عرض دين.
7. الاختيار يعرض معاينة (160px JPEG) فقط؛ الحفظ عبر `rfq_pilot_set_customer_photo` (مالك فقط) لا يحدث إلا بضغط «حفظ الصورة» الصريح. الإلغاء لا يكتب شيئًا.
8. قراءة الصورة الحالية عند أول فتح للقسم فقط (`select:'photo'` لصف واحد) — لا تُحمّل صور كل الزبائن في القائمة ولا تدخل المرآة المحلية.
9. رقم الجهاز والتطبيق والتوقيع كما في 128: `net.arena.rafiq`، لا تغيير في SQL أو الجسور أو CloudNativeBridge.
