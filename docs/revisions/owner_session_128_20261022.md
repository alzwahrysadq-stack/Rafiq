# رفيق 128: استعادة جلسة بيع المالك دون فقد الوردية

قاعدة الإصدار: d204918 (واجهة 127). versionCode الأدنى 128، versionName 0.3.2. نفس applicationId ومفتاح التوقيع. بناء Android على GitHub فقط.

## الخلل الذي ظهر على الهاتف
بعد اعتماد الهاتف وفتح وردية المالك بعهدة صفرية، أظهرت الواجهة لاحقًا «لا توجد وردية» ومنعت حفظ بيع برسالة جلسة عامل. قراءة الخادم أثناء التشخيص أثبتت أن وردية المالك الحالية مفتوحة بلا فواتير، وأن lease المؤقت انتهى. كان refresh يحاول heartbeat للمالك ثم يستعمل claim_worker عند الفشل ويصفر shift محليًا عند رفض العامل؛ ولم يكن يستعيد lease المالك عندما يصبح false.

## الإصلاح
- مسار owner-only يستعمل claim_owner_seller فقط، ثم my_open_shift لاستعادة معرف الوردية نفسه؛ لا RPC فتح/إغلاق وردية ضمن الاستعادة.
- استعادة عند التحديث الدوري والعودة للواجهة (visibilitychange/focus/pageshow) وقبل الحفظ، وقبل إرسال فواتير المالك المعلّقة بنفس معرفاتها.
- طلب استعادة واحد مشترك للطلبات المتزامنة. ردود قديمة بعد تبديل الحساب/الخروج/إنهاء وضع البيع لا تعيد تفعيل الجلسة.
- انتهاء lease/عطل الشبكة/رفض الجلسة لا يعني إغلاق الوردية، ولا يصفر آخر معرف معروف. لا يُصفّر المعرف إلا بعد قراءة خادم ناجحة تؤكد عدم وجود وردية مفتوحة.
- منع الحفظ المتصل أثناء تعذر التحقق/رفض الجلسة، مع زر استعادة واضح بدل اقتراح فتح وردية مكررة. خادم الصلاحيات والاعتماد وحماية الجلسة الواحدة لم يتغير.
- إعادة التحقق قبل فتح وردية؛ إن استعيدت واحدة موجودة فلا نفتح أخرى.
- إبقاء السلة والمدفوع كما هما خلال الاستعادة؛ واستعادة مستند المالك المحلي المعلّق من سجل الطابور أيضًا.
- زر «حفظ البيع» دون علامة نجاح وهمية. عنوان «نتيجة آخر حفظ للفاتورة» مع نص صريح عند عدم وجود مستند. لا يُعرض رقم فاتورة مؤكدة إلا بعد تحقق الإقرار والسطور الموجود سابقًا.

- مجموعة Pilot السابقة كاملة ناجحة: 54 فحص صلاحيات SQL، 58 دفتر، 397 عقد واجهة، 5 أساسيات، 86 مزامنة، 7 تنقل، ومسارات صلاحيات تكلفة الأصناف ونقل الأجهزة.
- Chromium حقيقي على مقاسات 360/390/412/820/1280. جميع الشبكات إلى خادم مصطنع معترض، لا اتصال بمتجر المستخدم. انتهاء lease ثم أحداث العودة استعادتها بمطالبة مالك واحدة، السلة والمدفوع بقيا كما هما. انتهاء lease ثانية قبل ضغط زر الحفظ الفعلي أنتج فاتورة مصطنعة واحدة وبدون claim_worker أو فتح وردية أخرى. لا أخطاء JavaScript غير معالجة ولا تجاوز أفقي.
